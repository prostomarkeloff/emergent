# Appendix B: Reading List

This appendix provides a curated map of the intellectual sources that underpin the book's argument. For each source: what it proves, and how it connects to the encoding.

---

## Foundations

### Reynolds 1972 — "Definitional Interpreters for Higher-Order Programming Languages"

**What it proves:** Functions and data are interconvertible. Defunctionalization turns closures into records + dispatch; refunctionalization reverses the transformation. The choice is a design decision, not a constraint.

**Connection:** emergent uses defunctionalization as architecture: capabilities are Reynolds' CLOSR records — frozen data carrying their free variables (fields like `value: int`) and their "lambda bodies" (compile_* methods). fold is Reynolds' `apply` — dispatch on record type. The entire encoding is Section 6 of this paper, applied as a design principle rather than a compiler optimization.

### Meijer, Fokkinga, Paterson 1991 — "Bananas, Lenses, Envelopes and Barbed Wire"

**What it proves:** For any inductively defined data type, the catamorphism (fold) is the unique structurally recursive consumer. Algebraic laws — fusion, banana split, universality — follow from uniqueness.

**Connection:** emergent's fold IS Meijer's catamorphism for lists. The capability tuple is the inductive data type. fold replaces the list constructors (tuple position) with the compile_* methods (operations). Fusion explains why compiler composition doesn't add traversals. Banana split explains why compile_fields runs all phases in one pass.

### Hutton 1999 — "A Tutorial on the Universality and Expressiveness of Fold"

**What it proves:** fold's universal property: `g [] = v ∧ g (x:xs) = f x (g xs) ⟺ g = fold f v`. Both proof principle and definition principle. Tupling (generating pairs/functions) extends fold's expressiveness beyond simple accumulation.

**Connection:** The universal property is why verify() works as a compilation target — verify IS a fold with a different algebra. Tupling is why compile_fields produces multi-phase results from one traversal. fold generating functions is why derivation (fold producing OpSpecs that materialize into handlers) works.

### Wadler 1998 — "The Expression Problem"

**What it proves:** Adding new data types AND new operations without modifying existing code, while preserving type safety and inspectability, is an open problem. Solutions exist (tagless final, object algebras) but sacrifice inspectability.

**Connection:** emergent dissolves the Expression Problem: new capabilities (data types) implement whichever protocols they want. New targets (operations) define new protocols. Both directions extensible. AND the data is inspectable — because capabilities are initial encoding (frozen data), not final encoding (opaque functions). isinstance dispatch is the mechanism that makes this work.

### Swierstra 2008 — "Data Types à la Carte"

**What it proves:** The Expression Problem can be solved in Haskell using coproducts of functors. Modular algebras compose via type class instances. The approach is extensible in both dimensions and uses initial encoding.

**Connection:** emergent simplifies Swierstra's approach by replacing recursive coproducts with flat tuples. Swierstra needs `Expr (Val :+: Add :+: Mul)` because expressions are trees. Capabilities are flat lists — the free monoid, not the free monad. This simplification gains commutativity and fusion that Swierstra's coproducts don't have.

## Complexity and Architecture

### Moseley & Marks 2006 — "Out of the Tar Pit"

**What it proves:** Complexity is the root problem. Mutable state and forced control flow are the primary causes. Most complexity in contemporary systems is accidental (not inherent in the user's problem). Prescription: avoid state and control; separate what remains into essential and accidental.

**Connection:** emergent eliminates accidental complexity by construction. No mutable state (frozen data, replace()). No forced control flow (capabilities are commutative within an axis). Derived representations (Pydantic, OpenAPI, SQL) are accidental — generated by fold, not written by hand. The five-file problem IS accidental complexity; emergent's encoding IS the elimination.

### Helland 2015 — "Immutability Changes Everything"

**What it proves:** "The truth is the log. The database is a cache of a subset of the log." Append-only computing is safe: idempotent, duplicate-tolerant, crash-recoverable. Immutable DataSets enable distribution without coordination.

**Connection:** theworld's Log IS Helland's log. Events are immutable facts. Computation state is derived by folding Lens queries over the Log. Workers die and restart without data loss because results are in the Log. ViewSnapshots are Helland's materialized views — typed events in the Log.

### Lamport 1978 — "Time, Clocks, and the Ordering of Events in a Distributed System"

**What it proves:** In a distributed system, "happened before" is only a partial ordering. Logical clocks provide total ordering by breaking ties with process IDs. Physical clocks drift and cannot be trusted for ordering.

**Connection:** theworld's Log provides total ordering: events have positions. `After(cursor)` implements "happened before." `AwaitConsistent(subscribers)` blocks until named computations have processed up to the caller's cursor. On InMemoryLog (single event loop) ordering is trivially consistent. On KafkaLog ordering is per-partition.

### Hewitt 1973 / Agha 1986 — The Actor Model

**What it proves:** Computation = communicating actors. Each actor: receives messages, creates actors, sends messages, designates next behavior. Asynchronous, one-way messaging. Quasi-commutativity.

**Connection:** theworld simplifies the actor model: all communication through one shared immutable Log, not point-to-point mailboxes. Eliminates: message ordering problems, dead letters, mailbox overflow, selective receive O(N). Preserves: identity, concurrent behavior, fault isolation (via scoped()).

## Category Theory and Algebra

### Milewski 2018 — *Category Theory for Programmers*

**What it proves:** Monoid = set + associative operation + identity. Free monoid = list. Catamorphism = unique homomorphism from initial algebra. F-algebra = carrier + evaluator. Coalgebra and anamorphism for generation.

**Connection:** Capabilities form a free monoid (tuple concat). fold is the unique homomorphism to End(Ctx). SchemaCompiler is a monoid under +. The encoding IS the free monoid consumed by its catamorphism — everything else (fusion, banana split, universality) follows from this one mathematical fact.

### Fong & Spivak 2018 — *Seven Sketches in Compositionality*

**What it proves:** Free constructions have universal properties. The free monoid on generators imposes no equations — minimum identifications. Composition is the central concept of applied category theory.

**Connection:** The free monoid on capability types imposes no equations between capabilities. `[MaxLen(255), Unique]` is not simplified to `[MaxLen(255)]` — both remain. fold interprets them in context. New capabilities add generators; existing generators are unchanged. This is the open-world property, formalized.

### Wadler 2015 — "Propositions as Types"

**What it proves:** Curry-Howard isomorphism: propositions = types, proofs = programs, simplification = evaluation. Gentzen's introduction/elimination pairs correspond to construction/deconstruction.

**Connection:** Capabilities are propositions ("max length is 255"). fold is proof construction. verify() is consistency checking (propositions contradicting = proof fails). Open-world dispatch is the subformula principle (only relevant propositions appear in each target's fold).

### Yang & Wu 2022 — "Fantastic Morphisms and Where to Find Them"

**What it proves:** Comprehensive taxonomy of recursion schemes: catamorphisms, paramorphisms, histomorphisms, anamorphisms, hylomorphisms, dynamorphisms, etc. Unification via adjoint folds.

**Connection:** emergent uses the simplest scheme — list catamorphism. This is deliberate: capabilities are flat and independent, so the advanced schemes (which handle dependencies between recursive positions) are unnecessary. The simplicity gains maximal algebraic laws. Exception: fold_expr for query expressions uses tree catamorphisms, because expressions ARE recursive.

## Software Design

### Tedinski 2018-2019 — Blog posts on software design

Key articles:
- "The Expression Problem" / "More on the Expression Problem" — data vs objects vs ADT
- "How Compilers Are Designed" — data as interfaces between pipeline stages
- "Data as a Mediator Between Computation and State" — represent actions as data, interpret separately
- "Types Are the Basic Tool of Software Design" — design IS types
- "The One Ring Problem" — more power = fewer properties = harder to reason
- "Composition vs Extension" — compositional reasoning requires independence

**Connection:** Tedinski provides the vocabulary for emergent's design choices. "Data as mediator" = capabilities. "One ring problem" = why fold is a catamorphism (not Turing-complete). "Composition vs extension" = why capabilities are commutative (compositional reasoning). "Types as design tool" = why the dataclass annotation IS the design.

## Programming Languages

### PEP 557 (2018) — dataclasses

Frozen dataclasses: immutable data with methods, hashable, comparable, compact (slots=True). The "record" in Reynolds' defunctionalization.

### PEP 544 (2019) — Protocol

Structural subtyping with runtime isinstance dispatch. Open-world: no inheritance, no registration. The dispatch mechanism that makes fold work.

### PEP 593 (2020) — Annotated

Type-level metadata attachment. Capabilities on fields. The "meaning on the field" principle.

Together: the three PEPs whose intersection IS the encoding. No other language provides all three in its standard library.
